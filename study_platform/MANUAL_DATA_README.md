# راهنمای ثبت دستی داده‌های مطالعه انسانی (E-AQI)

اگر می‌خواهید داده‌ها را **دستی** (خارج از پلتفرم وب، مثلاً روی کاغذ یا در
Excel) جمع کنید، از این گردش کار استفاده کنید. خروجی نهایی دقیقاً همان
`study.db` رسمی پلتفرم می‌شود و `analysis.py` بدون هیچ تغییری روی آن کار می‌کند.

## فایل‌ها

| فایل | نقش |
|---|---|
| `manual_data_ratings.csv` | ⭐ **فایل اصلی** — امتیاز هر محرک را اینجا وارد کنید |
| `manual_data_participants.csv` | یک ردیف برای هر شرکت‌کننده (سن، جنسیت و…) |
| `make_manual_template.py` | قالب‌های بالا را می‌سازد (126 تصویر × 5 شرط = 630 ردیف به‌ازای هر شرکت‌کننده) |
| `import_manual.py` | CSV ها را اعتبارسنجی و داخل `study.db` می‌ریزد |

## قدم ۱ — ساخت قالب (یک بار، قبلاً اجرا شده)

```
python make_manual_template.py            # اگر فایل از قبل باشد خطا می‌دهد
python make_manual_template.py --force    # بازنویسی عمدی (داده‌های تایپ‌شده پاک می‌شوند!)
```

## قدم ۲ — پر کردن `manual_data_ratings.csv`

ستون‌ها (مطابق خروجی رسمی سرور):

| ستون | الزامی | توضیح |
|---|---|---|
| `participant` | ✅ | شناسه شرکت‌کننده، مثلاً `P001` (هر شرکت‌کننده جدید باید اول در participants اضافه شود) |
| `base` | ✅ | شناسه تصویر پایه (در قالب از قبل پر شده — دست نزنید) |
| `cond` | ✅ | شرط محرک: `E` / `T` / `X` / `N` / `C` (در قالب پر شده). برای تکرار درون‌آزمونگر `E_R` یا `T_R` بنویسید و `is_repeat=1` |
| `is_repeat` | ✅ | `0` معمولی، `1` تکرار (در قالب پر شده) |
| `rating` | ✅ | ⭐ **ستونی که شما پر می‌کنید**: عدد صحیح 0 تا 100 (میزان آزارندگی) |
| `severity_delta` | — | فقط آزمون 2AFC: 0 تا 100 |
| `rt_ms` | — | زمان پاسخ به میلی‌ثانیه (اختیاری؛ برای QC پلتفرم مفید است) |
| `shown_left` | — | فقط 2AFC |
| `trial_index` | — | اگر خالی باشد خودکار شماره می‌خورد |
| `ts` | — | خالی بگذارید (زمان import ثبت می‌شود) |

نکته‌ها:
- **ردیف‌های `P000` سه ردیف اول، نمونه هستند** — import خودشان را نادیده می‌گیرد؛ دست نزنید.
- ردیف‌های خالی (rating تایپ نشده) نادیده گرفته می‌شوند؛ یعنی می‌توانید داده‌ی
  ناقص را هم لحظه‌ای import بگیرید تا پیشرفت را ببینید.
- هر شرکت‌کننده جدید: اول یک ردیف در `manual_data_participants.csv` با همان
  شناسه اضافه کنید، بعد 630 ردیفش را در ratings (می‌توانید کپی از ردیف‌های
  `P001` بگیرید) و امتیازها را پر کنید.

## قدم ۳ — بررسی و درج در دیتابیس

```
python import_manual.py --dry-run    # فقط اعتبارسنجی، چیزی نوشته نمی‌شود
python import_manual.py              # درج واقعی در study.db
```

اعتبارسنجی‌ها: وجود base در `stimuli/manifest.json`، شرط معتبر، بازه 0–100،
عدم تکرار ردیف، تطابق participant با فایل شرکت‌کنندگان. اگر یک ردیف خراب
باشد، **هیچ چیز** درج نمی‌شود و شماره ردیف مشکل‌دار گزارش می‌شود.

## قدم ۴ — تحلیل

```
python analysis.py --db study.db --out ../results/human_study_analysis
```

همچنین `python server.py --port 8000 --admin-token study2025` و صفحه‌ی
`/admin?token=study2025` → دکمه export، همان داده‌ها را JSON/CSV می‌دهد.

## اجرای موازی با سرور وب

هیچ تداخلی وجود ندارد؛ سرور و import هر دو به همان `study.db` می‌نویسند
(SQLite + WAL). فقط هنگام import داده‌ی دستی، جمع‌آوری آنلاین را موقتاً
نگه دارید تا شناسه‌ی شرکت‌کننده‌ها تصادفیِ سرور (مثل `Px7kq2m9ab`) با
شناسه‌های دستی (`P001`, `P002`, …) قاطی نشوند.

## چند نفر باید پر کنند؟

طبق پیش‌ثبت‌شده در مقاله (`manuscript/latex/main.tex`، بخش Participants):

| سناریو | تعداد داور | توضیح |
|---|---|---|
| حداقل معتبر (پیش‌ثبت) | **40 داور** | 45–50 نفر جذب کنید تا بعد از حذف‌های QC حداقل 40 بماند |
| توصیه‌شده | **51 داور** | power ≈ 0.80 در α = 0.01 برای d_z = 0.5 (با 40 نفر: power ≈ 0.72 در α = 0.05) |
| pilot کوچک | 12–15 داور | فقط اگر ادعاهای H1–H3 در مقاله به «pilot» بازنویسی شوند (فاز ۳ برنامه) |

بار کاری هر داور:
- قالب کامل هر نفر = **630 ردیف** (126 تصویر پایه × 5 شرط) ≈ 60 دقیقه داوری + تایپ
- ترجیحاً + **~126 ردیف تکرار (20٪)** با کد `ER`/`TR` و `is_repeat=1` — بدون آن، معیار QC
  «سازگاری تکرار ≥ 50٪» قابل محاسبه نیست و حذف داورها مستند نمی‌شود

نکته پوشش: چون هر نفر قالب کامل را پر می‌کند، هر محرک از همان اول 1 رتبه به ازای هر نفر
دارد؛ با 40 نفر، هر محرک 40 رتبه مستقل می‌گیرد — از حداقل پیش‌ثبتِ 12 رتبه مستقل برای هر
جفت به‌طور خودکار عبور می‌شود.
